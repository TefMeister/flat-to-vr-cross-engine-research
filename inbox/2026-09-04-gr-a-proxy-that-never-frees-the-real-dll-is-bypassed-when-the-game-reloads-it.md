# A proxy DLL that never frees the real DLL is bypassed the moment the game unloads and reloads it — Windows resolves a bare module name to whatever is already resident

Filed by: `/gr`, 2026-09-04 (found on `alan-wake-vr`; engine-agnostic, Windows loader behaviour)
Source topic: `alan-wake-vr/external-research/topics/2026-09-04-the-proxy-is-bypassed-on-reload-because-the-system-d3d9-is-never-freed.md`

- **The rule:** Microsoft's `LoadLibrary` remarks — *"When no path is specified, the function searches for loaded modules whose base name matches the base name of the module to be loaded. If the name matches, the load succeeds. Otherwise, the function searches for the file."* `[reported, first-party]`
- **The trap:** a game-folder proxy (`d3d9.dll`, `d3d8.dll`, `dxgi.dll`, `dinput8.dll`, …) loads the real DLL from `System32` by full path. If the game later `FreeLibrary`s the proxy — a capability probe at startup, a renderer restart — and the proxy did **not** `FreeLibrary` the real DLL in `DLL_PROCESS_DETACH`, the real one stays resident under the same base name. The game's next `LoadLibrary("d3d9.dll")` gets **it**, the game folder is never searched, and the proxy silently never runs again. The game works perfectly; the proxy log just stops.
- **A real case, with a primary-source fix:** Alan Wake probes `d3d9.dll` for 131 ms, unloads it, and loads it again for the renderer. ReShade did not work in Alan Wake until commit `74347b91d` (2019-12-19, 4.5.2): *"Free reference to the module loaded for export hooks (this is necessary for Alan Wake to work)"*. Our own Alan Wake proxy has the identical leak and the identical symptom (three launches, one probe cycle each, no `CreateDevice` ever seen). `[inferred-static 2026-09-04]`
- **Estate exposure:** by a grep of `staging/`, the proxies that load by system path and never free on detach are `alan-wake-vr`, `alice-madness-returns-vr`, `prince-of-persia-2008-vr`, `manhunt-2003-vr`, `mad-max-vr`, `burnout-paradise-vr`; `doom-2016-vr`, `enslaved-vr` and Psychonauts already free. It only bites where the game probes-and-reloads (Alan Wake so far), but it is one line to close everywhere. `[inferred-static 2026-09-04]`
- **Diagnostic signature worth recording:** a proxy log whose *only* content per launch is load → one export call → unload within ~100 ms, while the game visibly reaches gameplay, means "reloaded past us", not "the game crashed" and not "the game uses a different API".

Suggested library change: an entry in the proxy-DLL plumbing checklist — "free the real module on detach" — with the loader rule, the ReShade citation, and the log signature above; a one-line note on each exposed project's engine page.
